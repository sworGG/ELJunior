# ItPort (Elios 2.0) API discovery notes

Цель: подготовить нативную интеграцию расписания из `itport.ugrasu.ru` (Elios 2.0) вместо WebView.

Сейчас MVP использует WebView/Custom Tabs, чтобы:
- не ломать авторизацию
- автоматически использовать cookie/сессии браузера
- не зависеть от внутренней схемы API

Дальше нужно аккуратно «снять» внутренние API и стабилизировать интеграцию.

## 1) Как собрать логи эндпоинтов (самый быстрый способ)

### Вариант A: DevTools в браузере (рекомендуется)
1. Откройте `https://itport.ugrasu.ru/#/` в Chrome.
2. `F12` → вкладка **Network** → включите **Preserve log**.
3. Введите логин/пароль и залогиньтесь.
4. Откройте раздел расписания (обычно `#/timetable` или похожий).
5. В фильтре Network выберите **Fetch/XHR**.
6. Сохраните HAR: **Export HAR**.

Что выписать отдельно (текстом):
- все запросы к путям вида `/api/...`, `/auth/...`, `/oauth/...` (точные пути)
- какие заголовки используются (Authorization/Bearer/CSRF)
- какие cookie выставляются (имя cookie, домен, флаги; значения не публиковать)
- какой формат дат и таймзон (ISO, epoch, локаль)

### Вариант B: Network в Android WebView
Если нужно, можно временно включить `WebView.setWebContentsDebuggingEnabled(true)` и подключиться DevTools к WebView.

## 2) Что обычно встречается в SPA (гипотезы, которые надо подтвердить)
- **Auth**:
  - сессия через cookie (`Set-Cookie`) после POST логина
  - либо JWT/Bearer, получаемый из `/api/auth/login` или похожего
  - возможен CSRF-токен (заголовок `X-CSRF-Token`/`X-XSRF-TOKEN`)
- **Расписание**:
  - эндпоинт «кто я» (`/api/user/me`)
  - эндпоинт «расписание студента» (`/api/timetable?...`)
  - параметры: `dateFrom/dateTo` или `weekStart`, `groupId`, `studentId`

## 3) Схема, к которой будем приводить данные в приложении

В приложении уже есть доменная модель:
- `ru.ugrasu.eljunior.data.model.ScheduleItem`
- `ru.ugrasu.eljunior.data.model.DaySchedule`

Для нативной интеграции нужно будет добавить DTO-модели itport и маппинг:
- `ItportLessonDto` → `ScheduleItem`
- `ItportDayDto` → `DaySchedule`

Поля, которые важно иметь в ответе itport:
- предмет/тип пары
- преподаватель
- корпус/аудитория/адрес (если есть)
- время начала/конца
- дата/день недели
- признак четности недели (если есть) или правило повторяемости

## 4) План внедрения (после сбора Network логов)
1. Выделить стабильные эндпоинты и тип авторизации.
2. Добавить Retrofit `ItportApi` и модели DTO.
3. Реализовать `ScheduleRepository`:
   - логин/обновление сессии (если нужно)
   - запрос расписания на неделю
4. В `ScheduleScreen` добавить переключатель:
   - нативный режим (если работает)
   - fallback WebView (всегда доступен)

## 5) Чего НЕ делаем
- Не хардкодим логин/пароль.
- Не логируем токены/куки в релизе.
- Не привязываемся к приватным «внутренним» полям, если есть стабильная альтернатива.
